\section{Experiments and Results}
\label{sec:experiments}

We evaluate NeuroLocMap on five scenarios spanning simulated urban driving (CARLA Town05/03/07/10HD) and real-world highway driving (KITTI~07). The full system couples the vestibular-visual EKF core with two higher-level corrections: an online monocular scale branch (a lightweight regression head over a frozen depth foundation model, trained once on simulated data and frozen at deployment) and an experience-map loop-closure line built on learned scene embeddings. All higher-level components are \emph{trained once on simulation} and deployed \emph{zero-shot} on every test sequence, including the real-world one.

\subsection{Experimental Setup and Datasets}

\textbf{Implementation Details.} All experiments are conducted on a laptop workstation equipped with an Intel Core i5-12450H CPU (12th Gen, 8~cores), 16~GB RAM, and NVIDIA GeForce RTX 4050 Laptop GPU. The visual processing pipeline leverages GPU acceleration for HART-like feature extraction and Trans\-form\-er-in\-spired encoding (using simplified self-attention via global statistical modulation), while spatial cell computations run on CPU. The LSTM temporal module uses manually-tuned fixed gate values (input=0.55, forget=0.6, output=0.92) rather than learned parameters. The framework achieves real-time per\-for\-mance at $\sim$31~FPS on average across all test scenarios.

\textbf{Baseline Methods.} We compare NeuroLocMap against two baseline approaches:
(1) EKF Fusion --- a loosely-coupled 10-state Extended Kalman Filter
$(x,y,z,v_x,v_y,v_z,\phi,\theta,\psi,\log s)^\top$, where the 10th state
$\log s$ is the online-estimated logarithm of the monocular VO scale
(initialized to 0 and converging online from inertial observability). The state
is propagated with the IMU (gyroscope attitude integration plus bias-compensated
accelerometer dead reckoning, with a static-startup bias estimate) and corrected
with monocular visual-odometry measurements through four gated observation
branches: (i) a 1-D horizontal velocity-magnitude observation (VO inter-frame
displacement $\times$ online scale, over the true inter-update interval of IMU
step count $\times\Delta t$) that drives velocity correction and, when the
innovation exceeds the gate, directly reinitializes the velocity state;
(ii) a roll/pitch attitude observation; (iii) a short-window relative position
observation re-anchored to the current filter position every 30 frames, built
from the gyro-integrated heading direction $\times$ VO displacement magnitude
$\times$ online scale, so that the global VO heading drift does not enter the
fused position; and (iv) an independent scale observation estimating $\log s$
from turn kinematics (lateral specific force over yaw rate,
$|a_{\text{lat}}|/|\omega|$, normalized by the recorded VO speed, windowed
median). Each branch is guarded by a per-branch Mahalanobis chi-square gate
(0.99--0.999 level) to reject outliers. The observation noise matrix $R$ is
residual-adaptive (sliding-window smoothed innovation mapped to
$[R_{\min},R_{\max}]$, combined with a VO inlier-count quality factor), and the
covariance is updated in Joseph form with post-update regularization
(symmetrization + minimum-eigenvalue clamping). This is a representative classic
visual--inertial filter estimator in the family of
MSCKF/VINS-Mono~\cite{Mourikis2007,Qin2018}; and (2) Visual
Odometry (VO) --- a feature-based monocular VO baseline using ORB features
with epipolar-geometry pose recovery (Essential matrix + \texttt{recoverPose}),
without IMU fusion or loop closure. We additionally report
\emph{EKF+scale}: the same 10-state EKF whose scale state is driven by the deep scale head of the Methods section (no loop closure), which isolates the scale-branch contribution; and, where meaningful, the \emph{loop-closure line alone} (the experience-map pipeline without the scale branch).

\textbf{Implementation-Level Fairness.} For all methods, we use the same synchronized sensor streams and timestamps. Baseline trajectories are generated by our Python pipeline: on CARLA they are recorded during data collection (the EKF fusion baseline to fusion\_pose.txt, the VO baseline to visual\_odometry.txt, and the ground truth to ground\_truth.txt); on KITTI~07 the same EKF/VO pipeline is run offline on the raw public sequence with identical configuration. The evaluation then loads these trajectories and compares them against NeuroLocMap under identical sequences, ensuring differences reflect al\-go\-rith\-mic design rather than data or timing mismatches. All reported CARLA numbers correspond to data collected with the final EKF implementation (single global hyper-parameter set shared by all maps; collection parameters: agent speed 12~km/h, safe following distance 6~m, background traffic of 20 autopilot vehicles and 20 kinematically driven pedestrians), so the numbers in Table~\ref{tab:results} are directly reproducible from the public repository.

\textbf{Evaluation Datasets.} We evaluate on five diverse scenarios across two benchmark datasets (Table~\ref{tab:datasets}): (1) CARLA Simulation (Town05/03/07/10HD): simulated urban driving scenarios~\cite{dosovitskiy2017carla} with ground-truth poses and synchronized IMU-camera data, all re-collected with the same protocol and background traffic. Town05 (486~m) is the loop-richest route, crossing the same commercial streets repeatedly; Town03 (474~m) threads narrow alleys with strong viewpoint changes; Town07 (618~m) is a low-texture suburban loop; Town10HD (452~m) is an open layout with essentially a single revisit. (2) KITTI Odometry Sequence 07~\cite{geiger2012kitti}: real-world highway driving (692~m, 1101 frames) with high-quality visual features and limited loop opportunities, challenging systems on medium-length real-world trajectories.

\textbf{Evaluation Metrics and Alignment Calibers.} We employ standard SLAM evaluation metrics: Absolute Trajectory Error (ATE, RMSE after alignment)~\cite{sturm2012benchmark}, terminal drift rate (terminal error normalized by trajectory length), and Relative Pose Error (RPE, frame-to-frame consistency). Because NeuroLocMap recovers the metric scale online, the alignment protocol is itself part of the claim, and we evaluate \emph{every} method under two calibers, each estimated over the full trajectory and applied consistently to all methods: (i) \emph{full Sim(3) refit} (rotation, translation, and a single global scale, Umeyama/Procrustes) --- by construction the fitted scale absorbs any global scale error, so this caliber measures trajectory \emph{shape} and serves as an upper bound for all methods; and (ii) \emph{SE(3) rigid alignment} (Kabsch, rotation and translation only, no scale degree of freedom) --- a trajectory whose metric scale is wrong cannot be rescued by the aligner, so this caliber directly tests metric-scale recovery. Our metric-localization claim is stated in the SE(3) caliber: NeuroLocMap outperforms the EKF without any post-hoc scale fitting. We do not claim a globally scale-perfect system: residual global scale errors remain (Sim(3)-fitted scale factors 0.79--1.92 across scenarios), and the Sim(3) numbers should be read as the shape-only upper bound.

\subsection{Performance Results and Analysis}

\textbf{Quantitative Performance.} Table~\ref{tab:results} presents the quantitative comparison under both calibers. NeuroLocMap (full system) \emph{outperforms the 10-state EKF visual-inertial baseline on all five scenarios under both calibers}: by $+$16.5\% (KITTI~07) to $+$59.3\% (Town05) under the Sim(3) upper bound, and by $+$1.5\% (KITTI~07, the thinnest margin) to $+$33.9\% (Town05) under the SE(3) rigid caliber --- where an unrecovered metric scale cannot be absorbed by the aligner. The \emph{scale branch is the dominant contributor}: driving the EKF's scale state with the deep scale head alone (EKF+scale, no loop closure) already removes 13.1--32.7\% of the EKF's SE(3) error and 22.4--54.8\% of its Sim(3) error, and the full system adds a further loop-closure margin on Town05 ($-2.03$~m Sim(3)) and Town03 ($-0.76$~m). Against monocular VO, the full system wins on all five scenarios by $+$33.7\% to $+$68.8\% (Sim(3)). Two honest caveats accompany these headline numbers. First, on Town07 the scale branch \emph{alone} is the strongest configuration (27.90/29.21~m vs 28.75/31.51~m for the full system): the loop's marginal contribution there is slightly negative ($+0.84$~m), which we analyze in Section~\ref{sec:failure_analysis}. Second, on KITTI~07 the scale head does not transfer zero-shot to real imagery (Supplementary Section~S.1), so no EKF+scale row exists there and the KITTI result is carried by the loop-closure line alone.

\textbf{Performance by Scenario Type.} On the four CARLA towns (452--618~m), NeuroLocMap cuts the EKF's error by 22.4\% (Town10HD) to 59.3\% (Town05) under Sim(3), and by 13.1\% to 33.9\% under SE(3), while cutting monocular VO's error by 42.6--68.8\%. The gains decompose cleanly: the scale branch supplies the bulk (EKF$\rightarrow$EKF+scale), and the experience map contributes a further 0--2.0~m where the route is genuinely revisited (7--8 accepted links on Town05/03/07 versus a single inert link on Town10HD). The urban experience maps hold 90--481 experience nodes (Town05: 175, Town03: 90, Town07: 269, Town10HD: 481) with 67--481 visual templates.

On the real-world 692~m highway (KITTI~07), NeuroLocMap runs with the loop-closure line over the EKF core (the zero-shot scale branch is disabled; Supplementary Section~S.1) and still outperforms the EKF by 16.5\% under Sim(3) (18.45~m vs 22.09~m) and by 1.5\% under SE(3) (29.99~m vs 30.45~m), while beating monocular VO by 33.7\% (27.84~m). This validates that the vestibular-visual core plus learned loop closure remains effective on real-world driving --- and quantifies, honestly, how much of the framework's simulated-data advantage currently survives the domain gap.

\textbf{Representative Performance Analysis.} Figure~\ref{fig:representative_performance} visualizes two representative scenarios: Town05 (486~m, loop-rich mixed urban) and Town10HD (452~m, open layout). The top row shows per-method metrics (RMSE, drift, RPE, and template/loop counts); the bottom row shows the aligned per-frame position error evolution. On Town05, NeuroLocMap reaches 18.07~m RMSE --- 59.3\% better than the EKF (44.44~m) and 62.6\% better than monocular VO (48.26~m, whose drift reaches 24.2\% versus 4.6\%) --- while its experience map holds 175 nodes over 175 visual templates with 7 accepted links. On Town10HD, it reaches 14.44~m versus 18.61~m for the EKF ($+$22.4\%) and 35.86~m for VO ($+$59.7\%); the map holds 481 nodes but only a single accepted link, and the EKF+scale row (14.44~m) shows that essentially the entire gain comes from the scale branch, the loop being inert on this open layout. These two cases bracket the framework's operating regime: loop-rich urban driving, where experience-based re-anchoring adds global consistency on top of the metric-scale correction, and open layouts, where the system reduces to EKF+scale. Comprehensive results for all five datasets are given in Table~\ref{tab:results}.

\textbf{Framework Internal Representations.} The topological structure of the experience maps varies with scene revisiting structure: the CARLA maps hold 90--481 experience nodes (Town05: 175, Town03: 90, Town07: 269, Town10HD: 481) with 67--481 visual templates and 1--8 accepted PR links, while the KITTI~07 highway map is far denser (964 nodes, 929 templates over 692~m, $\sim$1.3 templates per meter), reflecting the high sampling rate of a visually distinctive, non-repeating scene. On loop-rich urban maps, the accepted re-anchors provide the global constraints that relax accumulated drift between revisits. The bio-inspired spatial cell representations demonstrate characteristic periodic firing patterns at different spatial scales (1.5~m to 12~m wavelength) for grid cells, and orientation-selective neural activity for head direction cells, confirming successful integration of ves\-tib\-u\-lar (IMU) signals for orientation estimation.

\textbf{Computational Performance and Complexity Analysis.} Table~\ref{tab:runtime} details per-module timing analysis. NeuroLocMap achieves real-time per\-for\-mance at $\sim$31~FPS average, with total pipeline latency of 32.1~ms. The grid cell update dominates computation (58\% of total time) due to 3D continuous attractor network dynamics, while experience map update (15\%) and visual template matching (7\%) remain lightweight. Visual processing achieves high throughput (2.1~ms, 469~Hz) despite dual-stream architecture, benefiting from the simplified $\mathcal{O}(N)$ self-attention implementation (global statistical modulation rather than full QKV operations) and efficient feature caching. The deep components add negligible cost: the frozen depth backbone and the scale head run outside the 31-FPS critical path (the head itself is $<$1~ms per frame on CPU), and the loop-closure line consumes precomputed frame embeddings.

\textbf{Theoretical Complexity.} The framework's computational complexity scales as: (1) Visual processing: $\mathcal{O}(HW)$ for image preprocessing plus $\mathcal{O}(N_f)$ for feature extraction, where $H \times W = 640 \times 480$ and $N_f \approx 300$ features; (2) Grid cell update: $\mathcal{O}(N_x N_y N_z)$ for 3D attractor dynamics with $30 \times 30 \times 10 = 9000$ cells; (3) Template matching: $\mathcal{O}(M \cdot d)$ where $M$ is template count (67--929) and $d$ is descriptor dimension (4096); (4) Experience map: $\mathcal{O}(K)$ for graph traversal with $K$ nodes (90--964). Total complexity is $\mathcal{O}(HW + N_x N_y N_z + Md)$, dominated by grid cell dynamics. Compared to learning-based methods requiring GPU matrix operations ($\mathcal{O}(N^2)$ for attention), our $\mathcal{O}(N)$ approximation enables CPU-only real-time execution.

\textbf{Hardware Requirements and Deployment.} The framework runs on commodity hardware without GPU acceleration for the SLAM pipeline itself: Intel Core i5-12450H CPU (8~cores, 2.0--4.4~GHz), 16~GB RAM, consuming $\sim$2~GB memory, dominated by the runtime state of the 3D grid-cell attractor network (visual template storage is $\sim$15~MB even in the densest map: 929~templates $\times$ 4096-dim descriptors $\times$ 4~bytes, plus experience map overhead). Peak CPU utilization reaches 45--60\% during grid cell updates, leaving headroom for concurrent processes. This lightweight footprint enables deployment on embedded platforms (e.g., NVIDIA Jetson Nano, Raspberry Pi 4) where learning-based SLAM methods requiring GPU inference (DROID-SLAM: 8~GB VRAM, TartanVO: 6~GB VRAM) are infeasible. Power consumption is estimated at 15--20~W (CPU-only) vs 50--80~W for GPU-accelerated methods, critical for battery-powered mobile robots.

\subsection{Component Ablation}
\label{sec:ablation}

\textbf{Scale Branch vs.\ Loop Line.} Figure~\ref{fig:ablation_and_vt}(a) decomposes the full system on Town05 (486~m, Sim(3) caliber): the full system reaches 18.07~m; removing the loop line (EKF+scale, no closure) yields 20.10~m; removing the scale branch (loop line over the unscaled EKF core) yields 41.14~m; the bare EKF is 44.44~m and VO 48.26~m. Two conclusions follow. First, the \emph{scale branch is the single dominant component}: it removes 24.3~m of the total 26.4~m gap between the EKF and the full system, consistent with the global scale being the largest monocular error source on this route. Second, the loop line contributes a further $-2.03$~m on top of the scaled core --- a real but secondary margin that scales with genuine revisiting structure (Section~\ref{sec:failure_analysis} quantifies where it vanishes). The same decomposition holds on Town03 (full 15.31 / EKF+scale 16.07 / loop-only 22.91 / EKF 23.36~m) and Town10HD, where the loop is inert and full system $\equiv$ EKF+scale (14.44~m).

\textbf{Learned Embeddings vs.\ Classical Descriptors.} Within the loop-closure line, replacing the learned scene embeddings with classical ORB-bag descriptors collapses the loop benefit: on Town05 the ORB-descriptor loop line yields 44.72~m --- statistically indistinguishable from the bare EKF (44.44~m) --- whereas the learned-embedding loop line reaches 41.14~m (Sim(3)). The persistence and orientation gates do the same work in both cases; it is the embedding quality that decides whether a revisited street is recognized at all.

\textbf{Visual Template Economy.} Figure~\ref{fig:ablation_and_vt}(b) shows visual template accumulation across the five scenarios: the framework grows 67--929 templates depending on scene repetitiveness, versus the $\sim$5 templates typical of classical RatSLAM~\cite{Milford2012}. The densest map is the visually non-repeating KITTI~07 highway (929 templates over 692~m, $\sim$1.3 per meter); the CARLA maps hold 67--481 (Town05: 175, Town10HD: 481, Town07: 263, Town03: 67), reflecting how much of each route is genuinely re-observed. Growth is monotone (templates are never deleted), and this selective, scene-adaptive template economy enables fine-grained place discrimination without unbounded map growth.

\subsection{Discussion and Insights}

\textbf{Performance Summary.} Figure~\ref{fig:performance_summary} summarizes the five-scenario comparison. Panel (a) shows NeuroLocMap below both baselines everywhere except the Town07 Sim(3) column, where EKF+scale is marginally best; panel (b) shows the improvement over the EKF under Sim(3) ($+$16.5\% to $+$59.3\%, bubble size proportional to route length); panel (c) shows the improvement over monocular VO ($+$33.7\% to $+$68.8\%). With only five scenarios we refrain from correlation statistics; the qualitative pattern is that the \emph{scale branch} contribution tracks the severity of the monocular scale error of each route (largest on Town05 and Town10HD, where the Sim(3)-fitted scale factors are 1.51 and 1.92), while the \emph{loop-line} contribution tracks genuine revisiting structure (7--8 accepted links on Town05/03/07, one inert link on Town10HD).

\textbf{When Does NeuroLocMap Excel?} Three conditions emerge:

\begin{itemize}
    \item \textbf{Monocular Scale-Error Regime} --- the scale branch pays off wherever the VO scale error is large and systematic: on Town10HD the raw EKF converges to a fitted scale of 0.65 (a 35\% scale error) yet 18.61~m Sim(3) / 57.38~m SE(3); with the scale head the same core reaches 14.44~m / 49.88~m. The SE(3) caliber is where this matters: it is exactly the error the Sim(3) refit would otherwise absorb.

    \item \textbf{Revisit-Rich Layouts} --- the experience map converts revisits into global constraints: Town05 (7 links) gains a further $-2.03$~m on the scaled core, Town03 (8 links) $-0.76$~m, whereas Town10HD's single inert link contributes nothing --- the system degrades gracefully to EKF+scale rather than being hurt.

    \item \textbf{Real-World Transfer with Honest Limits} --- on KITTI~07 the loop-closure line transfers zero-shot and delivers the $+$16.5\% (Sim(3)) / $+$1.5\% (SE(3)) margin; the scale head does not (Supplementary Section~S.1). The framework therefore remains effective on real data, but its simulated-data scale advantage is currently sim-only, and we say so.
\end{itemize}

\subsection{Failure Case Analysis}
\label{sec:failure_analysis}

\textbf{Town07: Loop Contribution Slightly Negative.} Town07 is the one scenario where the full system (28.75~m Sim(3) / 31.51~m SE(3)) is marginally \emph{worse} than EKF+scale (27.90/29.21~m): its single accepted-loop event contributes $+0.84$~m. The route is a low-texture suburban loop whose revisits are visually ambiguous; the embedding similarity of the accepted event sits close to the $\tau=0.94$ gate, and the resulting re-anchoring pulls a segment toward a slightly wrong map pose. The persistence gate (15 frames) and orientation gate (60$^\circ$) filter most such events elsewhere, but Town07 shows the residual false-positive risk of embedding-only loop verification. A geometric consistency check on accepted loops is the natural remedy and is left for future work.

\textbf{KITTI~07: Zero-Shot Scale-Head Failure.} The scale head, trained once on CARLA, predicts scale corrections in the wrong direction on real KITTI imagery (predicting $s\approx0.3$ where the route requires $\approx1.8$; Supplementary Section~S.1). Deploying it on KITTI degrades the EKF from 17.8~m to 23.1~m (Sim(3), real-VIO baseline) in our ablation, so the full-system KITTI result deliberately runs without it. This is the clearest evidence in the paper of the sim-to-real gap for the learned scale branch --- the loop line, whose embeddings transfer, carries the KITTI result instead.

\textbf{Town10HD: Inert Loop.} With a single accepted link that never fires, the full system equals EKF+scale bit-for-bit (14.44~m). This is by design (the gates prefer silence to a wrong re-anchor), and it bounds the downside of the loop machinery on open layouts.

\textbf{Summary.} NeuroLocMap excels on routes with large monocular scale error and genuine revisiting structure, from the 452--618~m CARLA towns to the 692~m real-world highway. Its two learned components degrade differently under domain shift: the loop embeddings transfer zero-shot, the scale head currently does not.

Two honest observations follow. First, every scale-consistent published system sits below 1.2\% RTE: stereo geometry fixes the scale intrinsically, and the sole monocular entry is a learned depth network whose output is already metric. NeuroLocMap, by contrast, is monocular plus IMU with no external scale reference, and Supplementary Section~S.1 shows that on real KITTI imagery the global scale is not recoverable from motion; the raw RTE (94.7/101.1\%) is dominated by this single global offset (the trajectory spans 1.9$\times$ the GT length) and is therefore not comparable to scale-consistent systems. Second, even under the most favorable monocular protocol --- a 7-DoF Sim(3) alignment that removes the global scale --- the per-frame RTE (72.1/75.2\%) remains far above the published figures, and excluding the 50 largest per-frame errors still leaves 38.2/46.9\%. The residual is a systematic per-frame scale drift, the per-frame projection of the same unrecoverable global scale (Supplementary Section~S.1): a property of the up-to-scale VIO core, not of the loop-closure / scale-recovery layer this paper contributes. Where that contribution is visible is global consistency: on KITTI~07 the loop-closure line reduces the EKF core's aligned ATE from 22.09~m to 18.45~m ($-$16.5\%), and across the four CARLA towns the full system reduces the EKF's ATE by up to 59.3\% (Table~\ref{tab:results}). NeuroLocMap is best read as a loop-closure and global-consistency layer on top of an up-to-scale VIO core, rather than a per-frame odometry competitor to scale-consistent stereo systems.

\textbf{Comparison with Learning-Based Methods.} Direct quantitative comparison with learning-based SLAM methods (DROID-SLAM~\cite{teed2021droid}, TartanVO~\cite{wang2021tartanvo}, DeepVO~\cite{wang2017deepvo}) is challenging due to fundamentally different evaluation protocols and training requirements. These methods require large-scale training datasets (e.g., TartanVO trained on 1M frames), GPU-intensive inference, and do\-main-spe\-cif\-ic fine-tuning for deployment. Nevertheless, we provide contextual comparison where data is available:

\begin{itemize}
    \item \textbf{Accuracy}: DeepVO reports 10.2\% drift on KITTI~07, where NeuroLocMap achieves 9.71\%. TartanVO achieves 2--3\% drift on CARLA but with extensive training. NeuroLocMap attains 2.9--11.7\% drift across the five test scenarios with its learned components trained once on simulation only.

    \item \textbf{Computational Efficiency}: DROID-SLAM achieves state-of-the-art accuracy but runs at 4--5~FPS (slower than NeuroLocMap's $\sim$31~FPS), limiting real-time deployment on embedded platforms.

    \item \textbf{Interpretability}: NeuroLocMap's bio-inspired components (grid cells, HDC, experience map) offer explicit spatial representations that can be visualized and debugged, unlike black-box deep networks.

    \item \textbf{Deployment Protocol}: NeuroLocMap's learned components are trained once on simulation and deployed zero-shot on all test sequences, including the real-world one, while learning methods often require per-domain adaptation.
\end{itemize}

Our approach targets a different design point: interpretable, train-once real-time localization and mapping for resource-constrained platforms where learning-based methods may not be feasible. For applications requiring maximum accuracy with ample computational resources and training data, learning-based methods remain superior.

\textbf{Limitations and Future Work.} While NeuroLocMap demonstrates strong per\-for\-mance across diverse scenarios, several limitations warrant discussion:

\begin{itemize}
    \item \textbf{Sim-to-Real Scale Gap}: the scale head transfers zero-shot within simulation (including the held-out town) but not yet to real imagery (Supplementary Section~S.1); closing this gap --- e.g., with scale supervision from sensors available on real vehicles --- is the main outstanding work item.

    \item \textbf{4-DoF Constraint}: The current height-discretized orientation representation suits ground vehicles but may limit applicability to fully 6-DoF scenarios with aggressive 3D maneuvers. Future work will extend to spherical orientation encoding for aerial platforms.

    \item \textbf{Template Man\-age\-ment}: The densest map (KITTI~07: 929 templates, $\sim$1.3 per meter) shows that on visually non-repeating scenes template creation is not yet sufficiently selective. Incorporating visual saliency or geometric verification could reduce false template creation and bound map size.

    \item \textbf{Loop Verification}: Accepted loops rely on embedding gates only; Town07 shows the residual cost of a marginally wrong re-anchor. Geometric consistency checks on accepted loops could further harden the gate chain.

    \item \textbf{Online Parameter Adaptation}: The framework uses fixed thresholds across scenarios (single global gate set, $\tau=0.94$). Learning-based or Bayesian approaches to automatically tune parameters based on environment characteristics could improve robustness.
\end{itemize}
